# API Docs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the API documentation to logged-in users only: two authenticated routes for agents and tools (`GET /api/openapi.json`, `GET /api/docs/agents`) and a Mantine "Docs" page inside the app, all generated from `docs/openapi.yaml` and guarded against drift by CI.

**Architecture:** A generator turns `docs/openapi.yaml` into two committed files under `src/api/generated/` (JSON spec, agent markdown as a TS string) that the API bundles. Two handlers serve them behind the normal authentication; they are registered by their own function so the browser demo bundle never contains them. The app fetches the JSON through `useProtectedApi` and renders it with a small renderer of our own (Mantine, no markdown or viewer library).

**Tech Stack:** TypeScript, Vitest (api and app projects), React 19 + Mantine 8, the `yaml` package already in devDependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-api-docs-design.md`

## Global Constraints

- Branch `feat/HOA-9-api-docs` (already checked out). Do not switch branches.
- Docs are for logged-in users only: both routes sit behind the existing authentication (session, JWT or token; a read token is enough). No public docs site, nothing in the demo build, no static docs files.
- No new runtime dependencies: no markdown library, no OpenAPI viewer, no syntax highlighter. Dev dependencies only if truly needed (prefer none).
- No `dangerouslySetInnerHTML` anywhere in the docs components; all spec text is rendered as text.
- The generator is deterministic (stable ordering, no timestamps). Generated files are committed; a test fails when they are stale. `yarn docs:generate` regenerates them.
- Both build scripts compile with `tsc --resolveJsonModule`; the Lambda build (`scripts/build-api-handler.cjs`) and the container build (`scripts/build-container.cjs`) must still work with the generated files (run `yarn build:container`; for the Lambda build run the `tsc` step it uses, or `yarn build` if the Auth0 env vars it needs are available as dummy values).
- UI follows `docs/brand.md`: theme tokens only, WCAG AA, colour never the only signal (HTTP methods appear as text), calm and low-stimulation, respects reduced motion, works on a phone.
- Conventional commits, subject under 72 characters, HOA-9 (and HOA-50 where relevant), control IDs where relevant (AUTH-01, AUTH-04, AUTH-13). Each commit ends with these two trailer lines: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_0164Feb96AP7ZVnA8tMDaooj`. `git add` specific files; never commit `.superpowers`.

## Review Focus

- No credential, a bad token, an expired token: 401 and no spec text in the body; a write-scope token and a session both get 200; `HEAD` works.
- The browser demo bundle never contains the spec or the docs handlers; the demo shows no Docs link and `/docs` shows nothing sensitive there.
- A spec string such as `<img src=x onerror=alert(1)>` or `[x](javascript:alert(1))` renders as plain text; nothing becomes markup or a link.
- A future spec edit that uses markdown the renderer does not support fails CI with a clear message instead of rendering garbage.
- Stale generated files fail CI; regenerating twice gives identical output.
- The page on a phone: sections collapsed by default, a filter with no matches shows a calm "nothing matches" message, no horizontal page scroll.
